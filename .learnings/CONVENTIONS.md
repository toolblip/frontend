# Project Conventions — Toolblip Rules & Preferences

## Git / Branching
- **Feature branches only** — never commit directly to `main`
- Branch → commit → push → PR → merge workflow for all changes
- Use merge commits (not rebase) when PR has diverged from main to avoid silent commit discard
- Write clear, descriptive commit messages: `feat(...)`, `fix(...)`, `chore(...)` prefix convention

## Deployment
- Railway auto-deploys on push to `main` via GitHub App — no manual `railway deploy` needed
- Build takes ~3-10 min after merge; check status via Railway GraphQL or dashboard
- Neon PostgreSQL is the database (not Railway Postgres)
- Cloudflare manages DNS

## Secrets / Environment
- Secrets go in `~/.openclaw/secrets/tb.env` (not in repo)
- Never commit `.env` files or any file with real credentials
- All env var access via `.env` file loader at startup

## Code Style
- Use TypeScript for all new frontend code
- Prefer `const` over `let`; avoid `var`
- Use named exports over default exports for utilities
- Sort imports alphabetically within groups

## Project Structure
- Frontend: Next.js 16 in `/frontend` or root of `toolblip` repo
- Backend: Laravel API (separate repo or `/api` — confirm location)
- Scripts: `/scripts` directory for automation scripts
- Cron jobs managed via Hermes/Crontinel

## Cron Jobs
- Cron jobs run silently; only message if something breaks
- Health check cron runs every 50 min, separate from SEO pipeline
- SEO cron runs at 11PM Dhaka nightly (`0 17 * * *` in UTC)
- Use Hermes cron for scheduling; never use system crontab

## Communication

- Use Claude Code (`ccbot` via terminal) for all coding and content writing tasks
- Inform user before using Claude Code

## SEO / Content

- Self-improve fires after every post in the SEO pipeline
- Never double-pick topics from queue (use state to prevent)
- Sitemap: submit to GSC after publishing; `https://toolblip.com/sitemap.xml`
