# GSC indexing audit, 2026-09-26

## What GSC and the live crawl showed

The September 21 GSC report showed 13 indexed URLs, 1,628 excluded, and
1,569 crawled but not indexed. The submitted sitemap index was last read
August 25 and showed zero children/discovered URLs.

On September 26, direct submissions of the tools (318 URLs), core (12),
and blog (126) sitemaps all showed **Success**. A full crawl of those 456
URLs returned HTTP 200 throughout, with no `noindex` directives. Only
`/about` and `/api-docs` were missing self canonical metadata.

Google's JWT URL inspection showed a successful crawl, indexing allowed,
and a self canonical. The URL remained crawled but not indexed, with a
temporary sitemap processing error. The indexing request was accepted
into the priority queue. GSC showed no manual actions or security issues;
there was no reported penalty.

## Sitemap dates and page canonicals

The index route stamped all three children with August 25. Core and tool
routes stamped every URL with August 26 despite September changes. These
constants didn't track changes to individual pages or child sitemaps.

The fix omits optional `lastmod` fields from the index, core, and tool
sitemaps until reliable dates are available. The shared serializer accepts
an optional date and omits missing or invalid dates. Blog entries retain
valid source dates; missing dates no longer receive the invented August 19
fallback. No build-time timestamps are substituted.

Self canonical metadata was added only to `/about` and `/api-docs`.
Sitemap URLs, priorities, frequencies, cache headers, and application
redirects are unchanged. Keep the current indexability gate: tools need
hand-written FAQ overrides to appear in the sitemap.

## The www redirect is active

`www.toolblip.com` initially returned a Railway fallback 404. The active
Cloudflare rule **Canonical www to toolblip.com** now matches the exact
hostname `www.toolblip.com` and returns a 301 to
`concat("https://toolblip.com", http.request.uri.path)`, with query-string
preservation enabled.

Live `curl` checks confirmed a 301 for the HTTPS www homepage. Both HTTP
and HTTPS www JWT deep links returned 301 while preserving the path and
query string. The canonical non-www JWT URL returned 200.

## Local checks passed; baseline CI failed

Regression tests reproduced six failures before the fix; all eight
sitemap tests then passed. Core URLs are checked against an explicit list,
tools against the actual indexable catalog, and the blog count against
source posts. These checks don't freeze normal catalog growth.

After the canonical additions, `npm test` passed all 314 tests across 31
files. `npm run build` passed TypeScript checks and generated 1,562 static
pages. The build ran outside the sandbox after the initial sandboxed
attempt stalled. Dependencies were installed with `npm ci`, with no
lockfile changes.

The built sitemap index parsed as valid XML with the same three children
and no `lastmod` elements. Built HTML for `/about` and `/api-docs` contained
exactly one self canonical link each. `git diff --check` passed. Source
review is complete, and an independent reviewer found no blocking issue.

Build warnings: deprecated `module.register()`, unset
`SHORT_LINKS_DATA_DIR`, edge-runtime static-generation limits, and
unsupported `z-index` rendering. These remain outside this change.

Baseline CI on `main` at `f14527d`, run `36220490321`, failed 13 auth/tool
tests and passed 112. The passing local checks above don't establish green
CI or resolve those baseline failures.

## What still needs monitoring

These technical fixes don't guarantee Google indexing, and the evidence
doesn't establish stale dates as the cause of the exclusions. Earlier
[recovery work](gsc-recovery-plan.md) documented a thin or duplicate tool
corpus; most of those historical examples now redirect. Retain the current
indexability gate rather than treating that history as a reason to submit
every tool.

Check Google's next sitemap fetch and later GSC reports for discovery and
indexing changes. A successful sitemap submission or an accepted indexing
request doesn't mean the URLs have been indexed.
