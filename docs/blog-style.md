# Blog style

Use this when you add or repair a post in `content/blog` or `src/content/blog`. The manifest publishes every Markdown file in those folders, so keep this note here.

Write the way you'd explain the tool to another developer. Contractions are fine. Short sentences. A heading should say what the section is for.

The Markdown URL is the same article, not a second draft. Don't add a note that the file is for agents, a model name, or a "copy prompt" button. The byline stays `Toolblip Team`.

Leave commands, paths, and numbers exact. If the routed tool doesn't have a control, don't describe it. Say what the page actually does, including what it skips (no signature check, JavaScript regex only, text Base64 only).

Skip em dashes except one in a long post if you really need it. Skip "leverage", "seamless", and "robust". Don't stack three adjectives. Don't end with "in summary".
