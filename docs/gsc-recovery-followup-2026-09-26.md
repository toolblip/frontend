## Product repairs and accurate content

- Twelve reviewed tools have explicit descriptions, examples, limits and feature lists in `data/reviewed-tool-content.ts`. `getToolContent` selects these before generated content. The existing server-rendered content section includes them in the initial markup, including closed details. Catalog descriptions and contradictory FAQs are updated too.
- Reading time rounds total seconds before division/remainder, so 199 and 399 words at 200 wpm show `1m 0s` and `2m 0s`. Case Converter and Word Counter only show success after the clipboard promise resolves and display failure when it rejects.
- Regex inputs now match the existing 2,000/50,000 character engine bounds. Base64 applies saved mode once; loading plaintext examples selects Encode.
- Grammar correction uses the clicked replacement, clears remaining offsets after a correction and ignores responses for edited text. Word frequency uses Unicode letter runs separated by punctuation, never empty tokens; its displayed percentages divide by the words remaining after filters. This is not language-specific segmentation.
- Generic image conversion uses the existing checked encoder. MIME or encoded-byte mismatch cannot create a mislabeled download; supported WebP fallback remains available.
- Retained SERP copy describes a manual approximation; readability names only Flesch ease, Flesch-Kincaid and SMOG; TypeScript copy names actual controls; keyword density takes plain text; word combinations cap at 2,000; JWT Tester verifies only HS256/384/512 shared-secret HMAC.

Existing active alias links in the affected blog sources and their generated manifest now point to canonical destinations.

## Verification and limits

Focused tests execute the real dispatcher with component markers, exercise actual selected component handlers with deterministic hook state, render server content and link sections, and test shared Markdown and image encoders. The hook harness is not browser hydration or an end-to-end user session. Added HTTP tests cover both flat and historical category aliases, including query strings. The final focused run passed 163 tests across five files. A live loopback check passed all 38 new redirect paths with query preservation. TypeScript and `git diff --check` also passed. The handoff at `/tmp/tb-product-recovery-result.md` records exact commands, the earlier import-time timeout and verification limits.

No full production build, commit, push, merge or deployment is part of this change. `lib/indexable-tools.ts` is left for the policy workstream. At the baseline, FAQ presence drives indexability, so the policy review must account for added/revised canonical FAQs before integrated acceptance. Accurate copy, static rendering and a working local redirect do not prove SEO recovery, indexability approval or Google indexing. No live GSC traffic or search performance evidence was used to pick canonicals.

The requested `ai-seo-geo-aeo` skill was not found in the advertised skill roots or the checked Hermes/Claude skill locations. The humanizer skill was applied to public copy; implementation decisions use the supplied audits and actual source behavior.
